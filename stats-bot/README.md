# Бот статистики CrazyGames

Щоранку GitHub Actions перевіряє кабінет розробника CrazyGames. Коли там з'являється статистика за вчора, бот:

1. надсилає в Telegram коротке зведення: 🟢 метрика покращилась, 🔴 погіршилась, ⚪ змінилась менше ніж на 1%;
2. додає день до історії (`metrics.json` у гілці `stats-data`);
3. будує таблицю метрик по днях `stats.html` (зелені клітинки — краще за попередній день, червоні — гірше) і надсилає її файлом у той самий чат.

Якщо до 13:00 (Київ) даних за вчора ще немає, бот пише, що статистика не оновилась. Якщо сесія в кабінеті закінчилась, він просить перелогінитись.

## Як це працює

Публічного API статистики в CrazyGames немає. Тому бот відкриває вашу сторінку статистики в headless-браузері (Playwright) зі збереженою сесією й перехоплює JSON, який завантажує дашборд. У цьому JSON він шукає часові ряди (масиви записів з датою і числами) — так бот не залежить від верстки сторінки.

## Налаштування (один раз)

### 1. Telegram-бот
- У [@BotFather](https://t.me/BotFather) створіть бота (`/newbot`) і скопіюйте токен.
- Напишіть своєму боту будь-яке повідомлення, потім відкрийте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` і візьміть звідти `chat.id`.

### 2. Сесія CrazyGames (на своєму комп'ютері)
```bash
cd stats-bot
npm install
npx playwright install chromium
npm run login
```
Відкриється браузер. Увійдіть у кабінет розробника, відкрийте сторінку статистики своєї гри й натисніть Enter у терміналі. Скрипт надрукує:
- URL сторінки статистики — впишіть його в `config.json` → `statsUrl` (або в змінну репозиторію `CG_STATS_URL`);
- довгий base64-рядок — це секрет `CG_STORAGE_STATE`.

Перевірте, що метрики знаходяться:
```bash
npm run discover   # нічого не шле, зберігає out/responses.json, out/extracted.json, out/page.png
```

### 3. Секрети репозиторію
Settings → Secrets and variables → Actions:

| Назва | Тип | Значення |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | secret | токен від BotFather |
| `TELEGRAM_CHAT_ID` | secret | ваш chat id |
| `CG_STORAGE_STATE` | secret | base64-рядок з `npm run login` |
| `CG_STATS_URL` | variable (необов'язково) | URL сторінки статистики, якщо не в `config.json` |

### 4. Запуск
Actions → **CrazyGames stats bot** → Run workflow (галочка `force` — надіслати повторно). Далі бот запускається сам кожні 30 хв з ~6:00 до ~14:30 за Києвом. Після сповіщення решта запусків того дня завершуються за кілька секунд.

## `config.json`

| Поле | Що робить |
|---|---|
| `statsUrl` | сторінка статистики гри в кабінеті |
| `timezone` | від якої дати рахувати «вчора», а також для `giveUpHour` |
| `giveUpHour` | після цієї години бот пише, що даних ще немає |
| `neutralThresholdPct` | зміни, менші за цей відсоток, не підсвічуються |
| `tableDays` | скільки останніх днів показувати в таблиці |
| `metrics` | список потрібних метрик з підписами, напр. `{"gameplays": {"label": "Сесії"}, "bounceRate": {"label": "Відмови", "lowerIsBetter": true}}`. Якщо порожній — беруться всі знайдені |
| `exclude` | числові поля, які не є метриками (id тощо) |
| `lowerIsBetter` | метрики, для яких зменшення — це добре (червоне/зелене міняються місцями) |

Сирі назви метрик дивіться в `out/extracted.json` після `npm run discover`.

## Корисне
- `npm run demo` — таблиця на випадкових даних (`out/demo.html`).
- `npm test` — тести парсера й кольорів.
- Сесія з часом закінчується — тоді повторіть `npm run login` і оновіть секрет.

## Важливо про деплой гри
Розклад GitHub Actions працює лише з **гілки за замовчуванням** (`main`). Якщо ваш скрипт деплою перезаписує `main` новим комітом з нуля (force-push білду), він видалить `.github/workflows/` і `stats-bot/`. Тоді або додайте ці папки до деплою, або тримайте бота в окремому репозиторії. Історія метрик лежить у гілці `stats-data`, тож деплой її не зачіпає.
